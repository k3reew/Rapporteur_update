## Изменения 0.3.0

Штатные профили используют промпты v4: v3 выпуска 0.3.0 с порядком важности, обязательными выводами и результатами и правилом сокращений из `summary.yaml`. Версия промптов входит в ключ кэша, версия подготовки поднята до 2.0.0, сводки до 2.1.1. Исторические профили v1/v2 доступны. Ревизия профиля также определяет актуальность предварительного отбора. Порты, независимые GPU, каталоги весов и хранилища сохраняют существующие настройки. [Правила обновления](release-0.3.0.md).

## Контекст

После переноса числовые владельцы вложенных данных должны соответствовать UID/GID запуска. Доступность корня сама по себе недостаточна; [инструкция восстановления](storage-permissions.md) описывает проверки и отдельную команду ремонта без изменения моделей.

Docker Compose читает `.env` в каталоге запуска и формирует переменные контейнеров. Python читает окружение процесса и файлы рядом с установленным пакетом. Каталоги на хосте и пути внутри контейнеров образуют разные уровни конфигурации.

Администратор задаёт оборудование и хранилище. Оператор может выбирать уже установленную модель и режим рассуждения через интерфейс. Промпты и бланки относятся к версии поставки.

В офлайн-комплекте путь Ollama по умолчанию `./models`, ASR — `./models/asr`. В исходниках это `./models/ollama` и `./models/asr`. При переносе `.env` между каталогами относительные пути необходимо сопоставить с новым местом запуска.

В контейнере app используются `RAPPORTEUR_DATA_DIR=/data`, `RAPPORTEUR_STATIC_DIR=/app/static`, `OLLAMA_URL`, `ASR_URL`, `ASR_ENABLED`, `OLLAMA_MODELS_PATH=/models/ollama`, `ASR_MODEL_DIR=/models/asr`. Первые два задаются образом, остальные подключением Compose. Для самостоятельного Python-запуска эти значения задаёт вызывающий процесс.

### Распознавание речи

ASR необязателен. `scripts/asr-mode.sh` переводит `ASR_MODE` в один из трёх режимов, Makefile после успешного `doctor` останавливает неиспользуемые варианты ASR, затем запускает выбранный профиль Compose и передаёт приложению `ASR_ENABLED`. Для `off` останавливаются оба варианта. Прямой `docker compose up` этот порядок не выполняет: для смены режима используйте `make up` или `make start`.

| `ASR_MODE` | Сервис | Устройство | Когда применять |
| --- | --- | --- | --- |
| `auto` | `asr` или нет | `gpu` при двух GPU и больше, иначе `off` | Значение по умолчанию |
| `off` | нет | — | Одна GPU, записей нет или они не нужны |
| `cpu` | `asr-cpu` | процессор, int8 | Одна GPU занята Ollama, записи нужны |
| `gpu` | `asr` | карта `ASR_GPU_ID` | Две карты и больше; `make doctor` требует карту, отличную от `LLM_GPU_ID` |

Без ASR подготовка не обращается к распознаванию. Запись без готовой расшифровки пропускается, а этап «Доклады» показывает предупреждение. Такой пропуск не кэшируется: после включения распознавания запись расшифруется. Расшифровка, сделанная раньше, берётся из кэша и без ASR. Состояние распознавания видно в «Настройках».

`ASR_REVISION` выбирает модель `Systran/faster-whisper-<размер>` для `make prepare`, по умолчанию `small`. Новая модель загружается и проверяется в `revisions/<размер>-<ревизия>/`. Файл `active.json` содержит относительный путь JSON-строкой и атомарно переключает активный каталог после проверки размеров, контрольных сумм и обязательных файлов. Прежние веса и файлы администратора сохраняются. Без `active.json` используется прежняя плоская структура. Ключи кэша расшифровок и подготовки записей включают манифест выбранной ревизии. Перед заменой остановите обработку и ASR; после переключения перезапустите app и ASR.

### Приоритет модели

`load_profile` сначала учитывает явно переданное имя, затем `RAPPORTEUR_PROFILE`, затем `default` файла `profiles.yaml`. В штатном Compose выбран `server`. При прямом запуске без переопределения default равен `local`.

Поверх базового профиля применяется выбор из таблицы `settings` с ключом `model`. Он заменяет имя модели, ревизию весов, квантование и флаг рассуждения. Лимиты контекста, ответа, температура и версия промпта наследуются от базового профиля. `PUT /model` с `model=null` возвращает базовый выбор.

| Профиль | Модель | Рассуждение | Лимит ответа | Контекст | Этапы в конфигурации |
| --- | --- | --- | --- | --- | --- |
| `local` | `qwen3.5:9b` | true | 12000 | 32768 | facts, facts-review, summary, critic |
| `local-fast` | `qwen3.5:9b` | false | 6000 | 32768 | facts, facts-review, summary, critic |
| `server` | `qwen3.5:27b` | true | 12000 | 32768 | facts, facts-review, summary, critic, vision, segmentation, recommendations |

Для server используется `weights_revision=local-manifest`. При загрузке профиля вычисляется SHA-256 файла манифеста в `manifests` или `manifests-v2`. Этот digest входит в профиль и ключи кэша. Выбранная через UI модель использует digest из ответа Ollama `/api/tags`.

Возможность рассуждения показывается по `capabilities` установленной модели. Для структурированных вспомогательных задач, включая визуальное описание, разбиение, сопоставление и рекомендации, `json_task` задаёт `think=False` и до трёх попыток. Факты и сводка используют флаг профиля. Поле `stages` описывает конфигурацию профиля, а вызовы определяются кодом соответствующего этапа.

### Формат весов

Ollama читает каталог с blobs и manifests. ASR разрешает `active.json`, если он есть, и читает выбранный CTranslate2-каталог с `model.bin`, `config.json`, `tokenizer.json` и подготовленным `manifest.json`; у large-v3 есть ещё `preprocessor_config.json`. Свободный файл Whisper `.pt` не является таким каталогом.

Стандартная серверная поставка использует Qwen 27B Q4_K_M и Whisper small; large-v3 задаётся через `ASR_REVISION`. Диагностическая 4B входит в подготовленный комплект от 14 ноября. Профиль `smoke` из локальной проверки был временным переопределением и описан в протоколе. Файл проекта не содержит этого профиля.

### Промпты и бланк

Активное `prompt_version=v4` выбирает `prompts/facts/v4.md`, `prompts/facts-review/v4.md`, `prompts/summary/v4.md` и `prompts/critic/v4.md`. Исторические профили с v1–v3 используют сохранённые промпты.

### Содержание сводки

Файл `summary.yaml` в корне репозитория и образа задаёт содержание сводки. Файл читается при обработке каждого доклада. Ошибка в нём завершает обработку доклада ошибкой, подробности — в журнале приложения (`make logs`).

| Ключ | Поставка | Назначение |
| --- | --- | --- |
| `min_sentences`, `max_sentences` | `6`, `10` | Число предложений основного текста; выводы автора — отдельным блоком до трёх |
| `priorities` | `[conclusion, result, method, problem]` | Порядок важности типов утверждений |
| `required` | `conclusion: 3`, `result: 3` | Сколько утверждений типа текст обязан использовать; если их меньше — все |
| `explain_abbreviations` | `true` | Расшифровка сокращений при первом упоминании по материалам доклада |
| `known_abbreviations` | РФ, США, ГБ и другие | Сокращения и единицы, которые не расшифровываются |

Настройки входят в ключ кэша сводки. Файл встроен в образ, поэтому правка применяется после `make up`. Критик вызывается с `think=False`, остальные три запроса используют флаг профиля. Загрузчик проверяет структуру и шаблоны промптов. Генерация выполняется через Ollama `/api/chat` с JSON Schema, параметрами `num_ctx`, `num_predict`, `temperature` и `think`.

Бланк `templates/starter/report.docx` использует переменные из `variables.yaml`, фильтры периода, падежей, количества и кавычек. Тему, имена и организации поставляет реестр. Счётчики рассчитываются кодом. Изменение промпта или бланка требует проверки соответствующего результата и версии.

### Лимиты и тайм-ауты

| Область | Значение по умолчанию |
| --- | --- |
| Документ/презентация/изображение | 200 МиБ |
| Текст заметок | 5 МиБ |
| Запись | 10 ГиБ, 10 часов |
| Число страниц | 300 |
| Изображение | 40 млн пикселей |
| Элементы Office ZIP | 10 000 |
| Распакованный Office ZIP | 2048 МиБ |
| Коэффициент сжатия ZIP | 100 для элементов от 1 МиБ |
| Рендеринг презентации | 180 секунд, длинная сторона 1600 пикселей |
| OCR страницы | 120 секунд, rus+eng |
| ffprobe | 30 секунд |
| ffmpeg порции | 300 секунд |
| Порция ASR | 300 секунд записи |
| HTTP-вызов ASR из app | 14 400 секунд |
| HTTP-вызов Ollama | 1800 секунд |
| Опрос интерфейса | 5 секунд |

Значения из Pydantic-конфигураций используются внутри кода и входят в ключи соответствующих кэшей. Для большинства таких лимитов отдельная переменная `.env` не предусмотрена. Большой контекст также ограничивается памятью выбранной GPU и общими процессами сервера.
