# Реализация пошаговой подготовки справки

Согласован пользователем вариант А. Один оператор, React/TypeScript/Vite, FastAPI/SQLite, Ollama/Whisper, три Docker-сервиса, офлайн-ресурсы.

1. Сохранить baseline, проверить существующие тесты.
2. Разделить API по предметным областям и чтение/запись SQLite. Сохранить API и схему хранения.
3. Отделить frontend API/типы/статусы/hooks от экранов. Четыре этапа materials/talks/review/report, processing — совместимый адрес review.
4. Реализовать компактные материалы, раскрываемые редакторы докладов, подтверждение и запуск с восстановлением после частичного сбоя. Сохранить legacy ручные привязки.
5. Переработать остальные экраны, темы, источники, рекомендации, справки. Защитить несохранённые правки.
6. Выполнить регрессионные, браузерные, интеграционные и офлайн-проверки, собрать релиз и описать обновление/откат.

Приёмка включает старую базу/отчёты, повторы и версии, частичную загрузку, мультимодальные источники, массовую проверку, перезапуск, офлайн-установку и 1366×768/1920×1080/узкое окно/клавиатуру. A100 проверяются на сервере, локальное оборудование указывается отдельно.

Реализация завершена в `codex/workflow-redesign`. Исходное состояние: `7936205be873de5664840fd05a27d42f5d99b150`. Подтверждённые проверки, состав поставки и ограничения — в [протоколе](../../benchmarks/2026-11-14-redesign.md). Нативный zoom и приёмка 27B/Whisper на двух A100 остаются проверками рабочего места/сервера.
