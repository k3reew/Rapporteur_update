# Руководство оператора

## Контекст

Оператор работает с одной конференцией через этапы «Материалы», «Доклады», «Проверка», «Справка». Дополнительные разделы содержат положения отделов и настройки. Фоновые задачи продолжаются после закрытия страницы, состояние можно перечитать с сервера.

Для первого знакомства используйте вымышленные материалы о кэшировании запросов. Пример соответствует предметной области тестов `fictional_talk.py`. Числа и названия в примере служат проверке пути данных.

Скачайте [текст учебного доклада](examples/talk.txt) и [учебное положение отдела](examples/department.txt). Текст доклада воспроизводит пять слайдов из `tests/fictional_talk.py`, положение взято из `tests/test_multimodal.py`. Загрузите `talk.txt` как «Текст выступления», а `department.txt` — в разделе отделов под именем «Отдел хранения». Даты учебной конференции можно задать 20–21 апреля 2026. Формулировки модели могут различаться, проверяется сохранение смысла и исходных чисел.

Для создания файлов вручную скопируйте следующие тексты в UTF-8.

**talk.txt**

```text
Кэширование запросов в распределённых базах данных. Иванов И. И., Институт примера.

Задача: снизить задержку чтения при неравномерной нагрузке.

Метод: сравнение политик LRU и LFU на стенде из 4 узлов с 32 ГБ памяти.

Результаты: при нагрузке 1000 запросов в секунду политика LFU снизила задержку на 23 %.

Выводы: LFU эффективнее LRU при неравномерном распределении запросов.
```

**department.txt**

```text
Отдел исследует методы ускорения запросов в базах данных.
```

## Ответственность компонентов

Оператор проверяет тип материалов, границы выступления, тему, авторов, содержание сводки и основания рекомендаций. При изменении источника он повторно обрабатывает доклад. Администратор обеспечивает доступность моделей, хранилища и сервисов.

Запуск задачи, её завершение и проверка человеком отображаются раздельно. До выпуска документа следует просмотреть предупреждения каждого включаемого доклада.

## Как это работает

### Создание и материалы

На странице «Конференции» введите название и нажмите «Создать». Для примера подойдёт «Учебная конференция по системам хранения». Даты и место заполняются на этапе справки.

Нажмите «Выбрать файлы» или «Выбрать папку». В папке сохраняется вложенный путь, например `Секция/01_Иванов/доклад.pptx`. Он помогает первоначальной привязке. Корневой `conference.yaml` при таком выборе пропускается. Экспорт реестра доступен отдельно в ручном редакторе.

Дождитесь итога загрузки. Успешные файлы остаются в списке даже при ошибках других. Повторная загрузка тех же байтов в ту же конференцию считается дубликатом. Если файл с прежним именем содержит новые данные, загрузите его под новым путём.

Откройте строку, чтобы проверить оригинал, предупреждение и назначение. PDF с текстом выступления следует обозначить как «Текст выступления». Для TXT/MD это особенно важно, поскольку исходное назначение — заметки слушателя. Программа конференции помогает определить темы и имена.

### Доклады

Нажмите «Подготовить доклады». Откроется этап предложений. Дождитесь результата извлечения и сопоставления. Для записи проверьте начало и конец каждого доклада по проигрывателю. Время указано в секундах от начала оригинала.

В раскрытой строке уточните тему и авторов. Перечислите нескольких авторов через точку с запятой. Для документов выберите страницы или оставьте весь файл. Для записи задайте оба конца интервала. Разделение создаёт два интервала по середине текущего диапазона, после чего их границы нужно уточнить. Объединение соединяет соседние предложения. Перенос материала меняет его доклад. Пустое предложение исключите из разбиения.

В старых конференциях доступен ручной реестр. Для ручной работы раскройте соответствующий раздел, добавьте название, проверьте привязки каждого файла и подтвердите их. Интервальные привязки редактируются в предложении.

«Подтвердить и обработать» сохраняет разбиение и запускает следующий этап. Если подтверждение прошло, а запуск вернул ошибку, повторите «Запустить обработку». Сохранённое подтверждение уже учтено. При конфликте версии скопируйте видимые правки в отдельный текстовый файл на рабочем компьютере. Для интервалов сохраните имя записи и обе границы. Затем отмените черновик, получите актуальное предложение и перенесите правки из файла. Обычная кнопка сохранения повторно отправляет устаревшую версию и конфликт не разрешает.

### Проверка сводки

В списке показаны очередь, текущий шаг и ошибки. Готовый доклад откройте для проверки. Нажмите метку `c1`, `c2` или другую рядом с предложением. Панель источника покажет утверждение, цитату, страницу или таймкод. Для записи доступно прослушивание соответствующего места, для слайда — изображение.

Сравните смысл предложения с источником. Проверьте числа, отрицания и условия результата. Для примера результат LFU должен сохранять «23 %» и «1000 запросов в секунду». Уточните тему «Кэширование запросов в распределённых базах данных» и автора «Иванов И. И.», если это подтверждается материалом.

Нажмите «Править», чтобы исправить предложения, выводы и тексты утверждений. Сохранение создаёт новую версию. Правка утверждения требует последующей проверки. При уходе доступны сохранение, отмена или продолжение редактирования.

«Подтвердить и следующий» подтверждает открытый доклад и переводит к следующему непроверенному результату. Верхние кнопки позволяют перемещаться между готовыми сводками. Для последнего доклада можно вернуться в список. «Подтвердить все готовые (N)» принимает только версии, разрешённые сервером, и сообщает причины пропуска остальных.

### Рекомендации отделам

В «Отделах» раскройте добавление или обновление положения. Укажите название, выберите новый отдел либо существующий и загрузите документ. Проверьте распознанный текст страниц.

Для примера загрузите готовое учебное положение под именем «Отдел хранения». Оно связывает отдел с методами ускорения запросов в базах данных. В проверенном докладе нажмите «Рассчитать рекомендации». Сопоставьте объяснение с фактами доклада и конкретными пунктами положения. Удалите неподходящие рекомендации или отредактируйте объяснение, затем подтвердите результат.

Пустой результат допустим при отсутствии конкретной связи. После изменения сводки или положения появится признак устаревания. Рассчитайте и проверьте рекомендации заново.

### Справка

Кнопка «Собрать справку» создаёт сохраняемое фоновое задание. Можно покинуть экран, при возвращении список заданий восстановится. Готовая версия содержит три формата. При неудаче раскройте задание и нажмите «Повторить сборку», повтор использует первоначальный снимок. Для выпуска с новыми правками создайте новую сборку. [Обновление и диагностика](release-0.3.0.md).

На этапе «Справка» задайте даты и место и сохраните сведения. Выберите доклады. Для обычного выпуска включайте проверенные актуальные сводки и подтверждённые рекомендации.

Флажок «Собрать, даже если не все сводки проверены» разрешает непроверенные и устаревшие сводки с предупреждениями. Использованное утверждение `needs_human` всё равно приводит к пропуску соответствующего доклада. Это отдельное условие допуска.

Нажмите «Собрать справку» и дождитесь версии. Проверьте предупреждения, темы, авторов и раздел рекомендаций. Скачайте DOCX, Markdown или PDF. Последующая сборка получает следующий номер, прежние документы остаются в списке.

### Что делать при затруднении

| Ситуация | Действие оператора |
| --- | --- |
| Повреждённый файл | Получить читаемый оригинал и повторить загрузку |
| Назначение выбрано неверно | Исправить его в строке материала и повторить подготовку |
| Текст распознан неверно | Свериться с оригиналом, улучшить исходник или исправить результат с проверкой |
| Граница режет реплику | Уточнить её по проигрывателю и границам распознанных сегментов |
| HTTP 409 | Перечитать актуальную версию и перенести сохранённую правку |
| Задача завершилась ошибкой | Прочитать сообщение, устранить причину и выполнить повторный запуск |
| Автор неизвестен | Уточнить по материалу или оставить явное обозначение неизвестного автора |
| Модель или ASR недоступны | Передать администратору сообщение и время ошибки |
| Нет дат для справки | Заполнить даты конференции и сохранить |

Перезагрузка страницы восстанавливает сохранённые сервером данные. Подтверждённые значения отличаются от несохранённого черновика. До закрытия страницы завершите сохранение или примите решение об отмене правок.

## Доступные функции

Вымышленный пример завершён, когда в справке есть тема и автор из проверенного реестра, сводка с корректным результатом LFU, подтверждённая рекомендация с опорами и три доступных формата версии. Оператор может затем изменить положение и увидеть устаревание текущей рекомендации, сохранив доступ к выпущенной версии.

В «Настройках» доступны светлая, тёмная и системная темы, выбор установленной модели и режим рассуждения. Технические сведения раскрываются отдельно. Выбранная модель применяется к последующей обработке.
