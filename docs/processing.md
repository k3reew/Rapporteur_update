# Извлечение материалов и подготовка докладов

## Контекст

Подготовка переводит разнородные файлы конференции в общий набор текстовых фрагментов с локаторами. Локатор указывает страницу, слайд, строку заметки или временной интервал. Этот слой сохраняет связь между содержанием и оригиналом для дальнейшей проверки цитат.

Расширение файла служит вспомогательным признаком. Приёмник проверяет содержимое, ограничения размера, читаемость, длительность и структуру Office-архива. Один файл может быть связан с несколькими докладами через непересекающиеся интервалы записи или выбранные страницы.

## Ответственность компонентов

API принимает поток `application/octet-stream`, проверяет относительный путь и вычисляет SHA-256. `inventory.inspect_file` классифицирует материал. `Storage.add_blob` публикует готовый оригинал жёсткой ссылкой с того же тома. `preparation.extract` строит и кэширует содержимое. `preparation.propose` собирает предложение, а `preparation.apply` проверяет и сохраняет решение человека.

ASR получает только SHA-256 уже загруженного оригинала в общем хранилище. Модель визуальной обработки получает подготовленные страницы. Оператор определяет смысловое назначение документа и проверяет границы выступлений.

## Как это работает

### Приём и извлечение

Поток сначала записывается во временный каталог рабочего хранилища. Проверка и вычисление хеша предшествуют регистрации. В БД действуют ограничения уникальности по содержимому и относительному пути внутри конференции. Дубликат возвращает существующую регистрацию, конфликт имени сообщает об ошибке.

| Материал | Назначение по умолчанию | Извлечение |
| --- | --- | --- |
| PPTX | `presentation` | Текст и заметки слайдов, PDF-рендеринг, изображения, OCR для слайдов без текста, визуальное описание |
| PDF | `presentation` | Текстовый слой и изображения страниц, OCR при отсутствии текста, визуальная обработка презентации |
| DOCX, DOC | `document` | Конвертация LibreOffice в PDF, текст и страницы, OCR пустых текстовых слоёв |
| TXT, MD | `notes` | Определение UTF-8, UTF-16 с BOM, CP1251, разбор заметок по строкам, при назначении `document` — текст выступления |
| JPEG, PNG, WebP, TIFF, HEIC/HEIF и читаемые Pillow изображения | `image` | Кадры/страницы, ориентация EXIF, OCR rus+eng и визуальное описание |
| Аудио и видео | `audio` или `video` по ffprobe | Моно PCM 16 кГц, Whisper, сегменты с абсолютными таймкодами |
| Программа | `program` по признаку или выбору | Текст для сопоставления тем и авторов |

Для Office и PDF установлен предел 200 МиБ и 300 страниц. Текст ограничен 5 МиБ, запись — 10 ГиБ и 10 часами. Изображение ограничено 40 млн пикселей, многокадровое — 300 страницами. ZIP проверяется по фактически распакованным данным, числу записей и коэффициенту сжатия. Подробные численные значения приведены в справочнике конфигурации.

### Распознавание и визуальная обработка

ASR проверяет длительность через ffprobe и читает запись порциями по 300 секунд. ffmpeg выделяет звуковую дорожку и приводит её к формату Whisper. Распознавание использует `vad_filter=True`, `beam_size=5`, `condition_on_previous_text=False`. Таймкоды каждой порции сдвигаются к началу исходной записи. Кэш учитывает оригинал, ревизию ASR, начало порции и версию алгоритма.

На стороне подготовки сегменты, начинающиеся в одну секунду, объединяются для уникальных меток стенограммы. OCR использует Tesseract `rus+eng`. Для презентаций и фотографий каждая подготовленная страница может дополнительно получить описание графиков и схем от модели. Для обычного документа применяется текст/OCR. Пустое визуальное описание не добавляет фрагмент.

### Предложение докладов

Запись анализируется окнами по 100 фрагментов с пятью предыдущими фрагментами для контекста. Модель возвращает индекс начала, тему и явно названных авторов. Вопросы, паузы и реплики ведущего включены в контекст выступления. При отсутствии найденных начал создаётся предварительное предложение от первого фрагмента. Конец доклада определяется следующим началом или длительностью записи.

Для документов сначала используются существующие привязки, папки и титульные сведения. Когда готовой связи нет, модель сопоставляет содержимое с кандидатами. Порог автоматического присоединения к кандидату равен 0,85. Далее учитываются известный доклад и точное совпадение темы. Неоднозначный материал формирует отдельное предложение для оператора.

### Карточка доклада

Каждое предложение получает карточку: тему, авторов, их организации и контакты, а также организации и контакты, которые не удалось отнести к автору. Источник — титульная и последняя страницы привязанных документов и презентаций. Строка темы, заметки, программа и описания изображений моделью не используются.

Сначала работают шаблоны `ingest/card.py`. Они находят e-mail, телефоны, сайты, `t.me` и ORCID, а организации — по признакам в короткой строке: университет, институт, лаборатория, АО, РАН, МГТУ и подобные. Сведение относится к автору, если стоит в одной строке с его фамилией, если e-mail содержит фамилию латиницей или если автор один.

Модель вызывается, только если у автора нет организации и шаблоны не смогли её назначить. Типичные случаи: несколько авторов с организациями на сносках ¹ ² или строка, похожая на организацию («Яндекс», аббревиатура), без известного признака. Из ответа принимается только подтверждённое страницами: организации — словами текста, контакты — среди найденных шаблонами, авторы — из списка доклада. Ответ кэшируется в `cache/card/`, сбой модели оставляет карточку с найденным шаблонами.

Значения реестра важнее найденного: при повторной подготовке исправленная оператором карточка сохраняется, заполняются только пустые поля.

### Подтверждение

Оператор отправляет номер версии предложения и список докладов. Код проверяет принадлежность файлов конференции, повторение докладов, границы страниц, длительность и пересечение временных интервалов. Временной диапазон полуоткрытый `[start_ms, end_ms)`, страницы задаются включительно. Для записи обязательны обе временные границы.

Подтверждение атомарно заменяет интервальные привязки конференции. Оригиналы сохраняются целыми. У затронутых докладов растёт `input_revision`, готовые результаты получают `stale`, а доклад без источников получает `insufficient_data`. Ранее записанные версии остаются в истории.

При сборке пакета для интервала принимаются только ASR-фрагменты, полностью помещающиеся в границы. Если граница проходит внутри реплики, пересекающая реплика исключается. Оператору следует сверяться с проигрывателем и границами распознанных сегментов.

## Доступные функции

Подготовка поддерживает смешанный набор файлов и отсутствие отдельных модальностей. Пользователь может исправить тему и авторов, задать страницы, разделить временной интервал, объединить соседние предложения и перенести материал. Ручные целые привязки сохранены для существующих конференций.

При изменении назначения снимаются связи файла, увеличивается ревизия затронутых докладов и ставится подготовка конференции. Повторное подтверждение предложения использует актуальную серверную версию. Если источники изменились параллельно, код возвращает 409 и интерфейс сохраняет черновик.

Сопоставление автора опирается на содержание и метаданные. Голосовая идентификация личности требует отдельного механизма. Достоверность OCR, распознавания и смысловых границ проверяется оператором по оригиналу.
