# Серверная приёмка «Репортёра» 0.5.0

Проверяйте на вымышленных материалах из `docs/examples/acceptance-0.5.0`. Набор содержит PPTX с графиком, DOCX, PDF, разноимённые материалы одного доклада, программу и вступительное слово. Эталон группировки и назначений находится в `expected.json`.

## Подготовка

1. Освободите карты, сохраните текущую установку и её образ Ollama. Выполните `nvidia-smi -L`, `nvidia-smi topo -m`, `nvidia-smi topo -p2p r` и `nvidia-smi topo -p2p w`. Запишите UUID, драйвер, тип связи и статус P2P. Проверьте работу NVIDIA Container Toolkit.
2. Используйте отдельный `COMPOSE_PROJECT_NAME`, локальный HTTP-порт и пустой `RAPPORTEUR_STORAGE` для каждого запуска. Для сравнения используйте приложение 0.5.0 и прежний образ и веса Ollama. Укажите `INFERENCE_ENGINE=ollama`, `OLLAMA_IMAGE`, `OLLAMA_MODELS_DIR`, `RAPPORTEUR_PROFILE` и `LLM_GPU_ID`. Зафиксируйте фактическую модель и её квантование. Если Ollama уже запущена в своей Docker-сети, заполните `OLLAMA_NETWORK` и `OLLAMA_URL`.
3. Проведите контрольный прогон Ollama с одним запросом в очереди, затем с двумя, если ранее использованная модель и профиль выдерживают этот режим. Укажите одинаковое значение `OLLAMA_NUM_PARALLEL` и `RAPPORTEUR_INFERENCE_SLOTS`. Для остальных прогонов верните `INFERENCE_ENGINE=vllm`.
4. Прогоните BF16 с `VLLM_MODE=bf16` при `RAPPORTEUR_INFERENCE_SLOTS=1` и `2`. Затем прогоните `gptq-single` и `gptq-dual` с настройками по умолчанию. При смене режима используйте `make down`, настройте `.env`, затем `make start`. Дождитесь готовности всех экземпляров.

## Измерения и качество

Для каждого профиля выполните одинаковые прогоны на пустых хранилищах. Повторите измерения не менее трёх раз на профиль после прогрева. При повторах одного профиля смена каталога хранилища через `make start` пересоздаёт приложение с тем же прогретым сервисом модели.

```bash
bash scripts/acceptance-vllm.sh http://127.0.0.1:18763 results/bf16-2-01
```

Сценарий проверяет предложение групп, соблюдение этапов подтверждения, документы и график, источники утверждений и выпуск в трёх форматах. Он сохраняет назначения модели до ручного решения. При несовпадении групп открывайте `preparation.json` и `expected.json`, чтобы увидеть различия. В `timeline.json` содержатся времена этапов, в `gpu.csv` загрузка и память каждой карты, в `services.log` ошибки загрузки и памяти, в `chart.json` распознанные значения графика.

Сведите выполненные прогоны в JSON. Повторные измерения указываются под тем же именем профиля. Для базовой медианы используйте имя `ollama`, остальным дайте различимые имена.

```bash
python3 scripts/compare-acceptance.py \
  ollama=results/ollama-01 ollama=results/ollama-02 ollama=results/ollama-03 \
  bf16-2=results/bf16-2-01 bf16-2=results/bf16-2-02 bf16-2=results/bf16-2-03 \
  gptq-2=results/gptq-2-01 gptq-2=results/gptq-2-02 gptq-2=results/gptq-2-03 \
  > results/comparison.json
```

Приёмка профиля включает корректное объединение файлов, сохранение точности назначений относительно Ollama, оба значения графика, проверяемые исходные цитаты и отсутствие OOM. Просмотрите сводки и подтверждённые фрагменты, чтобы сверить содержание. По GPU-трассировке проверьте работу обеих карт там, где профиль использует две. Сравните медиану времени полного разбора и отдельных этапов, отдельно учитывая одиночный и параллельный режимы.

После выбора профиля проверьте обновление на копии старого хранилища. Порядок резервного копирования и отката приведён в README комплекта.
