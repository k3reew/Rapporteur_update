# Серверная приёмка «Репортёра» 0.4.0

Проверка предназначена для двух A100 40 ГБ. Выполняйте её на вымышленных данных, с отдельным портом, именем проекта и пустым хранилищем для каждого прогона. Храните протоколы внутри контура.

## Запуски

1. Сохраните образ и веса текущей Ollama. Для сравнения используйте приложение 0.4.0 с текущей моделью и Whisper старой установки. При необходимости локально присвойте образу приложения тег `rapporteur:local` в **отдельном Docker-средстве приёмки**. Заполните `OLLAMA_MODELS_DIR`, `OLLAMA_IMAGE`, `LLM_GPU_ID`, `ASR_MODE` и задайте `INFERENCE_ENGINE=ollama`. Зафиксируйте фактические модель, квантование и распределение карт.
2. В vLLM запустите штатный профиль дважды с отдельным пустым хранилищем. В первом запуске задайте `RAPPORTEUR_INFERENCE_SLOTS=1`, во втором `RAPPORTEUR_INFERENCE_SLOTS=2`. Перед замером дождитесь доступности модели и выполните один разогревочный запрос. Для воспроизводимости повторите каждый замер три раза на пустом хранилище.
3. В корне соответствующего комплекта после запуска выполните, подставив свой порт и новый каталог для протокола.

   ```bash
   bash scripts/acceptance-vllm.sh http://127.0.0.1:18763 ./acceptance-run
   ```

Сценарий добавляет положения, обрабатывает презентацию, PDF и DOCX, сохраняет назначения и цитаты, выпускает три файла справки и проверяет диапазон расшифрованной записи. Для одинаковой нагрузки он подтверждает одни и те же заранее размеченные назначения во всех прогонах. Это отделяет качество машинного предложения от времени подготовки одинакового отчёта. Скрипт сохраняет мониторы GPU, топологию и журналы сервисов.

## Условия переключения

- По `classification.json` и `screening.json` сверить доклады для одного, нескольких и ни одного отдела. Для спорных примеров сверить основания и наличие действия проверки. В `*.summary.json` открыть источники для каждого проверяемого тезиса.
- Сопоставить вывод по графику со слайдом, числа и ограничения с оригиналами. Проверить, что релевантные доклады содержат ключевые тезисы и выводы, а карточки содержат только названия и авторов. Числа и цитаты без опоры считаются дефектом.
- Проверить по `gpu.csv` работу обеих A100, по `services.log` отсутствие OOM, по `topology.txt` тип связи. В `stages.txt` сравнить длительности ASR, разбора изображений, отбора и сводок. Для сравнения полного времени используйте интервал от `materials_ready` до `drafts_finished` из `timeline.json`. Требуется улучшение медианы относительно текущей установки без ухудшения качества.
- Повторить ручной маршрут на рабочем разрешении. Открыть источники, перезагрузить вкладку во время обработки, проверить даты, скачать DOCX, Markdown и PDF.
- На отдельной копии прежнего хранилища проверить миграцию и доступность старых выпусков. При ошибке использовать порядок возврата из README комплекта.

Локальные автоматические проверки с тестовыми ответами модели подтверждают поведение приложения. Качество и скорость реального профиля подтверждаются этим серверным протоколом.
