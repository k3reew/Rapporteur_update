# Установка, обновление и обслуживание

## Содержание документа

<!-- codebase-analysis-ai:scope:start -->
Подготовка офлайн-поставки, перенос, первый запуск, обновление, резервное копирование и откат. Раздел предназначен администратору сервера с Docker и отдельными GPU для моделей.

## Контекст

Рабочая поставка состоит из образов app, ASR и Ollama, каталогов весов и файлов запуска. На машине подготовки используются исходники и интернет для получения закреплённых зависимостей. Сервер запускает загруженные образы и локальные модели.

Пути в примерах заменяются фактическими каталогами. Рабочее хранилище располагается на файловой системе Linux. Веса доступны для чтения, хранилище — для записи пользователю запуска.

## Симптомы и задачи

Инструкция охватывает первую установку, смену версии приложения, перенос на другой массив, конфликт порта, восстановление из бэкапа и остановку. Для подробного сопоставления сообщений используется таблица диагностики в конце.

## Подготовка

Требуются Linux, Docker Engine, Compose v2, GNU make, драйвер NVIDIA и NVIDIA Container Toolkit. Ollama нужна одна GPU. Распознавание речи на отдельной карте требует второй GPU. При одной карте ASR по умолчанию выключен или работает на процессоре (`ASR_MODE`, [конфигурация](configuration.md#распознавание-речи)). Серверный профиль использует Qwen3.5 27B Q4_K_M и Whisper small.

Проверьте окружение следующими командами.

```bash
docker version
docker compose version
nvidia-smi -L
make --version
df -h .
docker info --format '{{.DockerRootDir}}'
```

Поставку от 14 ноября можно ориентировочно оценивать в 28 GiB с диагностической 4B. Для каталога, загружаемых образов, распаковки и запаса рекомендуется около 60–70 ГБ, далее учитывается рост оригиналов и кэша. Проверять нужно и раздел Docker. Носитель должен поддерживать файлы крупнее 4 ГБ, например ext4 или exFAT.

Управление GPU определяется доступностью карт и памятью на сервере. UUID из `nvidia-smi -L` устойчивее порядковых номеров. Перед запуском проверьте занятость GPU другими проектами.

## Порядок действий

### Подготовка с интернетом

В полном исходном репозитории создайте `.env` из примера, задайте пути весов и UUID карт.

```bash
cp .env.example .env
make prepare
make bundle
```

`make prepare` собирает образы и получает основную Qwen и ASR. При имеющихся весах используются их каталоги. Для добавления заранее скачанной диагностической модели в поставку применялась команда ниже.

```bash
make bundle MODEL="qwen3.5:27b qwen3.5:4b"
```

### Перенос

Копируйте весь `bundle`, включая `.env.example`, модели, образный архив и `SHA256SUMS`. Полное инженерное руководство из `output/pdf/rapporteur-guide.pdf` перенесите рядом отдельным файлом. Действующая цель `make bundle` копирует в runtime-поставку README, WORKFLOW, ACCEPTANCE и VALIDATION. Полная навигация по исходникам доступна в репозитории и едином PDF. Пример для носителя и каталога сервера приведён ниже.

```bash
TRANSFER_DIR=/media/USB/rapporteur
mkdir -p "$TRANSFER_DIR"
cp -r bundle/. "$TRANSFER_DIR/"
cd "$TRANSFER_DIR"
sha256sum --check --quiet SHA256SUMS
sync
```

На сервере скопируйте содержимое носителя в выбранный каталог, например `/srv/rapporteur`. Права на этот каталог должен выдать администратор. Установку выполняйте обычным пользователем с доступом к Docker.

```bash
cd /srv/rapporteur
make install
```

Установка проверяет контрольные суммы, загружает три образа и создаёт `.env`, если его ещё нет. Каталог Ollama в комплекте содержит `blobs/` и `manifests/`, а ASR находится в `models/asr`.

### Настройка сервера

В `.env` укажите фактические UUID и пути.

```dotenv
LLM_GPU_ID=GPU-uuid-первой-карты
ASR_MODE=gpu
ASR_GPU_ID=GPU-uuid-второй-карты
OLLAMA_MODELS_DIR=./models
ASR_MODELS_DIR=./models/asr
RAPPORTEUR_STORAGE=./storage
RAPPORTEUR_PROFILE=server
WEB_BIND_ADDRESS=127.0.0.1
WEB_PORT=18763
OLLAMA_IMAGE=ollama/ollama:0.40.13
```

Для доступа с рабочего компьютера задайте внутренний IP сервера в `WEB_BIND_ADDRESS`. При занятом порте выберите свободный `WEB_PORT`. Порты Ollama и ASR доступны внутри Docker. Значения лимитов CPU и RAM настраиваются в той же `.env`.

```bash
make config
make doctor
make start
make ps
```

`make doctor` проверяет Compose, разные GPU, модельные каталоги, порт, запись в хранилище и не менее 5 ГБ свободного места. Это предварительная проверка. `make start` использует `--no-build --pull never` и ждёт состояния сервисов. Откройте адрес сервера с выбранным портом.

### Обновление существующей установки

1. Скачайте одну ранее выпущенную справку во всех трёх форматах и сохраните рядом результат `sha256sum` для каждого файла. Сохраните прежний комплект с архивом образов, `.env` и контрольными суммами.
2. Остановите прежнюю установку командой `make down`.
3. Создайте полный бэкап рабочего хранилища. Пример предполагает путь `/srv/rapporteur/storage`.

```bash
mkdir -p "$HOME/rapporteur-backups"
tar --acls --xattrs -czf "$HOME/rapporteur-backups/storage-before-update.tar.gz" -C /srv/rapporteur storage
cp /srv/rapporteur/.env "$HOME/rapporteur-backups/env-before-update"
```

4. Разместите новый комплект отдельно, например в `/srv/rapporteur-new`, и выполните там `make install`.
5. Перенесите нужные значения старого `.env`. Пути к прежним весам и хранилищу задайте абсолютными.

```dotenv
OLLAMA_MODELS_DIR=/srv/rapporteur/models
ASR_MODELS_DIR=/srv/rapporteur/models/asr
RAPPORTEUR_STORAGE=/srv/rapporteur/storage
```

6. Проверьте `make doctor`, выполните `make start` и откройте старую конференцию. Сверьте привязки, сводки и скачивание старой справки.

Если прежний запуск выполнялся из исходников, каталог Ollama обычно заканчивается на `models/ollama`. В примере выше показана структура готового комплекта. Одно хранилище обслуживает одна активная версия app.

### Регулярная работа

`make ps` показывает состояние, `make logs` открывает журнал, `make down` останавливает сервисы с сохранением данных. Для подробного журнала применяйте `docker compose logs --tail 100 app asr asr-cpu ollama`. Выход из просмотра журнала — Ctrl+C.

На сервере используются install, config, doctor, start, ps, logs и down. Команды prepare, bundle, check и lock относятся к полному исходному репозиторию.

## Проверка результата

После установки проверьте `healthy`, список моделей в настройках и один короткий текст выступления. Пройдите подготовку, подтверждение, обработку, проверку и выпуск справки. Проверьте имя и тему в DOCX/PDF, затем повторите с короткой записью и таймкодами.

После обновления скачайте прежнюю справку и сравните её хеш с сохранённым. Выполните остановку и повторный запуск и убедитесь в сохранности данных. Запишите версии образов, модели, UUID GPU, настройки и результаты в протокол приёмки.

`GET /health` app подтверждает доступность процесса. `/health` ASR проверяет наличие `model.bin`. Реальная работа моделей подтверждается отдельным сквозным запросом. На целевом сервере измеряются время, память и качество на разрешённых материалах.

## Откат

Остановите новую установку. Отложите её текущее хранилище, чтобы сохранить результаты работы после обновления. Восстановите полный бэкап на прежний путь.

```bash
mv /srv/rapporteur/storage /srv/rapporteur/storage-after-update
tar --acls --xattrs -xzf "$HOME/rapporteur-backups/storage-before-update.tar.gz" -C /srv/rapporteur
```

Перейдите в прежний комплект и выполните `make install`, чтобы вернуть предыдущие образы с локальными тегами. Затем выполните `make doctor` и `make start` с прежними настройками.

SQLite-бэкап `rapporteur.db.before-v1.bak` относится к миграции схемы. Рабочий откат включает также оригиналы, страницы и справки из полного бэкапа.

## Диагностика и обращение за помощью

| Сообщение или симптом | Проверка и действие |
| --- | --- |
| Порт занят | Проверить `WEB_PORT`, выбрать свободный порт |
| Нет GPU или одинаковые UUID | Сверить `nvidia-smi -L`, Toolkit и `.env` |
| Нет манифеста Qwen | Указать каталог над blobs и manifests, проверить тег профиля |
| ASR не готов | Проверить полный каталог CTranslate2 и доступность выбранной карты |
| Permission denied | Сверить права чтения весов и записи в хранилище |
| Ошибка SHA-256 | Повторно перенести комплект из проверенного источника |
| Недостаточно памяти GPU | Проверить другие процессы, лимиты и параметры контекста |
| Ошибка документа | Получить читаемую версию, проверить LibreOffice/OCR в журнале |
| Диск заполняется | Оценить рост оригиналов, кэша и справок, подготовить перенос хранилища |

Для обращения сохраните время, действие, идентификатор конференции/доклада и фрагмент журнала. Перед передачей материалов учитывайте правила организации по конфиденциальности. Проект использует доверенный сетевой доступ к единой рабочей области.
