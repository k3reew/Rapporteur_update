### Зависимости

Python требует `>=3.12,<3.13`. FastAPI, Pydantic, docxtpl, PDFium, Pillow, RapidFuzz и остальные зависимости объявлены в `pyproject.toml`, точные разрешённые версии — в `uv.lock`. ASR устанавливается отдельной группой с faster-whisper, CTranslate2 и CUDA-библиотеками. Фронтенд использует React 19.3.1, TypeScript 6.0.3, Vite 8.3.4 и Vitest 5.0.5. Версия npm-пакета фронтенда `0.1.0` отличается от версии приложения `0.2.0`.

Обновление зависимостей выполняется через `make lock` на машине с сетью. Политика даты отсечения задаётся `exclude-newer` и `NPM_BEFORE`. После изменения lock-файлов собираются новые образы и повторяются проверки.

### Команды

В корне полного репозитория с подготовленным `.env` доступны следующие команды.

```bash
make config
make check
make lint
make test
make format
```

`make check` вызывает обе группы проверок. `make lint` включает Ruff, проверку форматирования, mypy, ESLint и TypeScript. `make test` выполняет pytest, Vitest и production-сборку Vite. `make format` изменяет Python-файлы, поэтому перед запуском нужен просмотр текущего diff.

Контейнеры `dev` и `web-dev` подключают исходники с хоста и работают с `network_mode: none`. Их сборка требует заранее доступных базовых образов и зависимостей либо машины подготовки с сетью. Готовый комплект содержит runtime-образы, полный набор dev-инструментов в него не включается.

Для профильного запуска существующих тестов после сборки dev-образа применяются команды.

```bash
docker compose run --rm dev pytest tests/test_upgrade.py
docker compose run --rm web-dev sh -c 'vitest run src/WorkflowPages.test.tsx'
```

Production-интерфейс обслуживается тем же приложением FastAPI. Автоперезагрузка отдельного Vite-сервера в текущем Compose не настроена. Его конфигурация содержит React и Vitest, прокси `/api` в ней отсутствует. Для проверки полного пути используется собранный интерфейс через порт приложения.

### Внесение изменений

Перед изменением изучаются маршруты, предметные функции, контракты, существующие данные и их тесты. Для ошибки сначала воспроизводится сбой. Проверяются ответы API, фиксация транзакции до ответа, версионные конфликты, повторное выполнение и старые данные. Длительные обращения к моделям выполняются вне write-транзакции.

При изменении HTTP-контракта обновляются снимки OpenAPI и справочник API. При изменении хранения проверяется восстановление старой установки и сохранность ранее выпущенных файлов. Промпт, профиль, версия модели и шаблон входят в условия воспроизводимости и кэширования. После изменения нужен повторный выпуск комплекта.

Правила истории и PR описаны в `docs/git.md`. Исторический backlog отражает этапы проекта. Текущее поведение определяется реализацией и действующими тематическими документами.
