# Репортёр

Веб-сервис для подготовки справок по материалам конференций в закрытом контуре. Материалы можно загружать в любом сочетании: презентации, текст выступления, фотографии слайдов, аудио и видео. Облачные API при обработке не используются.

Сервис извлекает текст, предлагает разделение общей записи на доклады, собирает факты с цитатами и готовит сводки. Оператор проверяет результат. Справка содержит темы, авторов, содержание докладов и рекомендации отделам с основаниями из загруженных положений.

**Важно:** автоматическое разбиение, распознавание и интерпретация графиков могут ошибаться. Предложения нужно подтвердить в интерфейсе. Результаты тестов с подставной моделью не являются оценкой качества Qwen и ASR на записях из зала.

## Что потребуется

- Linux, Docker Engine с Compose v2, GNU make, драйвер NVIDIA и NVIDIA Container Toolkit.
- Две доступные GPU: Qwen работает на одной, ASR — на другой. Для целевого сервера предусмотрены две A100 40 ГБ; объединение их памяти не требуется.
- SSD для весов, SQLite и рабочего хранилища. Размер комплекта зависит от образов и моделей; перед подготовкой разумно иметь 70 ГБ свободного места, дополнительно к материалам конференций. HDD можно использовать для архивов и резервных копий.
- На машине подготовки нужен интернет. На рабочем сервере интернет не требуется.

Пакеты драйвера, Docker и NVIDIA Container Toolkit администратор устанавливает заранее; они не входят в комплект приложения.

## Быстрый запуск на машине с интернетом

В корне репозитория:

```bash
cp .env.example .env
```

Выполните `nvidia-smi -L`. В `.env` укажите **разные UUID карт**, например:

```dotenv
LLM_GPU_ID=GPU-uuid-первой-карты
ASR_GPU_ID=GPU-uuid-второй-карты
OLLAMA_MODELS_DIR=./models/ollama
ASR_MODELS_DIR=./models/asr
RAPPORTEUR_STORAGE=./storage
WEB_BIND_ADDRESS=127.0.0.1
WEB_PORT=18763
RAPPORTEUR_PROFILE=server
```

UUID выше — образцы; замените их значениями своего сервера. Можно использовать номера `0` и `1`, но UUID устойчивее к смене порядка устройств.

```bash
make prepare
make up
```

`make prepare` собирает образы и скачивает Qwen3.5 27B Q4_K_M и Whisper large-v3. Это длительная операция. `make up` выполняет предварительную проверку и запускает сервисы. Откройте **http://127.0.0.1:18763**.

Если модели уже скачаны, укажите существующие каталоги и переходите к `make up`. Запуск не скачивает модели автоматически.

На машине подготовки без GPU можно выполнить `make prepare` и `make bundle`: GPU нужны для рабочего запуска. Если Docker отсутствует, веса отдельно можно получить командой `python -m rapporteur.offline_models --kind all --directory models` из установленного Python-окружения проекта.

## Где должны лежать модели

```text
models/
├── ollama/
│   ├── blobs/sha256-...
│   └── manifests/registry.ollama.ai/library/qwen3.5/27b
└── asr/
    ├── model.bin
    ├── config.json
    ├── tokenizer.json
    ├── preprocessor_config.json
    └── manifest.json
```

Ollama может использовать `manifests-v2/` вместо `manifests/`. Укажите **каталог над `blobs/`**, а не путь к отдельному GGUF. ASR требует формат CTranslate2; произвольный файл Whisper `.pt` ему не подходит. Не копируйте веса в `src/` или в образ вручную.

Веса подключаются к сервисам только для чтения. Контрольные суммы и ревизии фиксируются при подготовке. Серверный профиль читает digest фактического манифеста Ollama; он входит в ключи кэша обработки.

## Перенос в закрытый контур

На машине с интернетом после `make prepare`:

```bash
make bundle
```

Перенесите **весь каталог `bundle/`**, включая скрытый `.env.example`. На целевом сервере, в каталоге комплекта:

```bash
make install
# Отредактируйте созданный .env: GPU UUID, пути, адрес и порт.
make doctor
make start
```

`make install` проверяет SHA-256 и загружает образы. `make start` использует `--no-build --pull never`. Подробности обновления, резервного копирования и диагностики: [офлайн-установка](docs/offline.md).

Чтобы открыть сервис с другого рабочего места, задайте в `WEB_BIND_ADDRESS` IP сервера во внутренней сети. Встроенных учетных записей нет: доступ разрешается доверенному оператору или через корпоративный шлюз. Не открывайте порт в недоверенную сеть.

Ollama и ASR не публикуют порты на хосте. При конфликте веб-порта поменяйте `WEB_PORT`; существующие проекты останавливать не нужно. Подключение существующей Ollama: [отдельная инструкция](docs/ollama.md).

## Как подготовить справку

1. На странице «Конференции» создайте конференцию. Даты и место заполняются на этапе «Справка».
2. В «Материалах» загрузите файлы или папку. Папки вида `Секция/01_Иванов/` помогают группировке, но не обязательны.
3. Проверьте назначение файлов. PDF может быть презентацией, текстом выступления или программой. TXT/MD по умолчанию — заметки слушателя; для полного текста выступления выберите «Текст выступления».
4. Нажмите **«Подготовить доклады»**. Откроется этап «Доклады»; дождитесь завершения. Страницу можно закрыть: задача остается в очереди.
5. Проверьте темы, авторов, начало и конец каждого доклада. Время указано в секундах от начала оригинала; запись можно прослушать. При необходимости разделите интервал, объедините соседние доклады или перенесите материалы. Пустую карточку после переноса исключите из разбиения.
6. Нажмите **«Подтвердить и обработать»**. Откроется «Проверка». Если запуск не удался после подтверждения, повторите **«Запустить обработку»**; разбиение сохранено. Для заранее разложенных текстовых презентаций можно использовать обычные привязки без автоматического разбиения.
7. В «Проверке» откройте сводку. Ссылки `c1`, `c2` показывают цитаты и страницы/таймкоды источника. Исправьте тему и авторов при необходимости.
8. Используйте **«Подтвердить и следующий»**. Кнопки «Предыдущий» и «Следующий» открывают соседние готовые сводки. В списке **«Подтвердить все готовые (N)»** подтверждает только актуальные результаты без предупреждений и визуальных утверждений, требующих человека.
9. В разделе **«Отделы»** загрузите положения и проверьте распознанный текст. В карточке проверенного доклада нажмите **«Рассчитать рекомендации»**, проверьте основания и подтвердите рекомендации. Можно изменить объяснение или убрать рекомендацию; несколько отделов либо отсутствие совпадений допустимы.
10. В «Справке» сохраните даты и место, выберите доклады, соберите новую версию и скачайте DOCX, Markdown или PDF. В конце находятся рекомендации отделам. Непроверенные/устаревшие рекомендации не включаются, приложение показывает предупреждение.

Если автора установить нельзя, справка явно сообщает «Автор не установлен». Неизвестную тему можно оставить предварительной. Визуальные выводы из схем и графиков включаются только после индивидуального подтверждения. Программа конференции помогает привязке, но не служит источником научных результатов доклада.

## Команды и обслуживание

| Команда | Назначение |
| --- | --- |
| `make prepare` | Образы и модели на машине с интернетом |
| `make up` / `make start` | Запуск со сборкой / офлайн без сборки |
| `make doctor` | Проверка настроек, GPU, порта, каталогов и места |
| `make config` | Проверка Compose без запуска |
| `make ps` / `make logs` | Состояние / журнал |
| `make down` | Остановка с сохранением данных |
| `make check` | Ruff, mypy, pytest, ESLint, TypeScript, Vitest и сборка |
| `make bundle` / `make install` | Подготовка / установка офлайн-комплекта |
| `make pull MODEL=qwen3.5:9b` | Скачать дополнительную модель Ollama |

CPU и RAM ограничены параметрами `APP_*`, `LLM_*`, `ASR_*` в `.env`. Начальная параллельность Qwen — один запрос, контекст — 32K. Скорость и качество нужно измерить на целевом сервере; заранее обещанного времени обработки нет.

Рабочие данные лежат в `RAPPORTEUR_STORAGE`: оригиналы, SQLite, версии сводок, кэш и справки. Для резервного копирования остановите сервис и скопируйте **весь каталог**. При первом обновлении схемы SQLite создается `rapporteur.db.before-v1.bak`; это дополнительная страховка, а не замена полному бэкапу.
