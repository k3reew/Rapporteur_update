# Установка и обновление без интернета

Рабочая поставка состоит из трех образов: приложение, ASR и Ollama, каталогов весов и файлов запуска. В этой поставке также включена небольшая Qwen3.5:4b для диагностики; серверный профиль использует Qwen3.5:27b. Во время работы контейнеры не скачивают пакеты, модели, шрифты или словари. Docker Engine, Compose, драйвер NVIDIA и NVIDIA Container Toolkit устанавливаются администратором отдельно.

## Перенос готового комплекта и первый запуск

Готовый комплект находится в `bundle/` исходного репозитория. Его размер при текущих моделях составляет около 28 GiB (точный размер см. `du -sh bundle`). На целевом сервере уже установлены Docker Compose и NVIDIA Container Toolkit. Также понадобятся работающий драйвер NVIDIA, Docker Engine и GNU make.

### Шаг 1. Копирование на носитель

На машине подготовки откройте терминал в корне репозитория. Укажите путь к новому каталогу на подключенном носителе вместо `/media/USB/rapporteur`.

```bash
TRANSFER_DIR=/media/USB/rapporteur
mkdir -p "$TRANSFER_DIR"
cp -r bundle/. "$TRANSFER_DIR/"
cd "$TRANSFER_DIR"
sha256sum --check --quiet SHA256SUMS
sync
```

Отсутствие вывода и код завершения 0 означают совпадение контрольных сумм. Копирование `bundle/.` включает скрытый `.env.example`. Носитель должен поддерживать файлы больше 4 ГБ. Дождитесь завершения `sync`, затем извлеките его средствами ОС.

### Шаг 2. Копирование на сервер

Войдите на сервер под обычным пользователем с доступом к Docker. Подключите носитель. В следующей команде замените `/media/USB/rapporteur` фактическим путем к комплекту.

```bash
mkdir -p "$HOME/rapporteur"
cp -r /media/USB/rapporteur/. "$HOME/rapporteur/"
cd "$HOME/rapporteur"
sha256sum --check --quiet SHA256SUMS
docker version
docker compose version
nvidia-smi -L
make --version
df -h .
```

После проверки файл `images.tar.gz` и каталог `models/` должны находиться рядом с Makefile. Для комплекта, образов Docker и временной распаковки заложите около 60 ГБ свободного места, затем добавьте запас для материалов конференций. Если Docker хранит данные на другом массиве, проверьте его свободное место тоже. Путь показывает `docker info --format '{{.DockerRootDir}}'`.

### Шаг 3. Загрузка образов

```bash
make install
docker image ls
docker run --rm --pull never --gpus all --entrypoint nvidia-smi ollama/ollama:0.40.13 -L
```

Установка повторно проверяет SHA-256, загружает три образа из `images.tar.gz` и создает `.env`. В списке образов появятся `rapporteur:local`, `rapporteur-asr:local` и `ollama/ollama:0.40.13`. Последняя команда должна показать карты внутри контейнера.

### Шаг 4. Настройка

Откройте `.env` любым текстовым редактором. Укажите разные UUID карт из `nvidia-smi -L` в `LLM_GPU_ID` и `ASR_GPU_ID`. Параметры моделей уже подготовлены для каталога комплекта.

```dotenv
OLLAMA_MODELS_DIR=./models
ASR_MODELS_DIR=./models/asr
RAPPORTEUR_PROFILE=server
RAPPORTEUR_STORAGE=./storage
ASR_DEVICE=cuda
WEB_BIND_ADDRESS=127.0.0.1
WEB_PORT=18763
```

Для открытия с рабочего компьютера замените `WEB_BIND_ADDRESS` внутренним IP сервера. При занятом порте выберите свободный `WEB_PORT`. У приложения нет собственных учетных записей, доступ предоставляется в доверенной корпоративной сети или через корпоративный шлюз. Порты Ollama и ASR остаются внутри Docker.

### Шаг 5. Запуск

```bash
make doctor
make start
make ps
```

`make doctor` проверяет пути, две разные карты, место и веб-порт. `make start` создает рабочее хранилище и запускает загруженные образы с `--no-build --pull never`. Дождитесь состояния `healthy` у app, asr и ollama. Откройте `http://IP-СЕРВЕРА:18763`, подставив выбранные IP и порт. При привязке к `127.0.0.1` интерфейс доступен с самого сервера.

### Шаг 6. Первая справка

1. В «Настройках» проверьте доступность Ollama и модели `qwen3.5:27b`.
2. Создайте тестовую конференцию и загрузите короткий текст выступления. Для TXT/MD выберите назначение «Текст выступления».
3. Нажмите «Подготовить доклады», проверьте тему и автора, затем «Подтвердить и обработать».
4. На этапе «Проверка» дождитесь сводки, проверьте цитаты и подтвердите результат.
5. В «Справке» сохраните даты, выберите доклады, сформируйте версию и скачайте DOCX и PDF. Убедитесь, что указаны тема и автор.
6. Повторите с короткой аудиозаписью. Проверьте текст, таймкоды и границы докладов.
7. В «Отделах» загрузите положение. Для проверенного доклада рассчитайте и подтвердите рекомендации, затем сформируйте новую справку.

Во время обработки проверьте `nvidia-smi`. Qwen и ASR должны использовать выбранные разные GPU. Первый запрос включает загрузку модели в память и может занять больше времени. Проверьте скорость и качество на материалах организации.

### Шаг 7. Диагностика и остановка

```bash
make ps
docker compose logs --tail 100 app asr ollama
make down
```

Для просмотра журнала в реальном времени выполните `make logs`, выход из просмотра — Ctrl+C. `make down` останавливает сервисы, данные остаются в `storage/`. Для повторного запуска используйте `make start`.

## 1. Подготовка нового комплекта на машине с интернетом

Нужны исходники, Docker и make. GPU для подготовки не требуются.

```bash
cp .env.example .env
make prepare
make bundle
```

Проверенная поставка 14 ноября включает также диагностическую 4B (`make bundle MODEL="qwen3.5:27b qwen3.5:4b"`). При сборке без аргументов готовятся `qwen3.5:27b` и `Systran/faster-whisper-large-v3`. Локальные пути к весам задаются в `.env`. Веса ASR должны включать `model.bin`, `config.json`, `tokenizer.json` и `preprocessor_config.json`. Комплект может занимать десятки гигабайт; исходные модели и их копия в комплекте требуют отдельного места.

Каталог комплекта:

```text
bundle/
├── images.tar.gz
├── models/
│   ├── blobs/
│   ├── manifests/registry.ollama.ai/library/qwen3.5/27b
│   └── asr/
├── scripts/doctor.sh
├── compose.yaml
├── Makefile
├── .env.example
├── README.md
├── WORKFLOW.md
├── ACCEPTANCE.md
├── VALIDATION.md
└── SHA256SUMS
```

`models/` в комплекте — каталог Ollama; ASR находится в его подпапке `asr/`. На исходной машине структура по умолчанию другая: `models/ollama/` и `models/asr/`. `.env.example` комплекта уже учитывает это различие.

`SHA256SUMS` охватывает образы, модели и файлы запуска. Не изменяйте их между подготовкой и `make install`. Перенесите весь каталог, включая скрытые файлы. Носитель должен поддерживать файлы крупнее 4 ГБ, например ext4 или exFAT. Модели не хранятся в Git.

## 2. Установка на сервере

В каталоге комплекта:

```bash
make install
nvidia-smi -L
```

Откройте `.env`, созданный установкой. Заполните:

```dotenv
LLM_GPU_ID=GPU-реальный-UUID-первой-карты
ASR_GPU_ID=GPU-реальный-UUID-второй-карты
OLLAMA_MODELS_DIR=./models
ASR_MODELS_DIR=./models/asr
RAPPORTEUR_STORAGE=/srv/rapporteur/storage
WEB_BIND_ADDRESS=127.0.0.1
WEB_PORT=18763
RAPPORTEUR_PROFILE=server
```

Каталог `/srv/rapporteur/storage` — пример. Администратор должен создать его с правом записи для пользователя, который запускает make. Используйте Linux-файловую систему. Веса должны быть доступны этому пользователю для чтения.

Затем:

```bash
make doctor
make start
make ps
```

Откройте `http://127.0.0.1:18763`. Для доступа с другого компьютера укажите внутренний IP сервера в `WEB_BIND_ADDRESS`. У приложения нет собственных учетных записей; доступ ограничивается доверенной сетью/корпоративным шлюзом.

`make start` не собирает образы и не обращается к реестрам. `make up` на машине без интернета не используйте. Ollama и ASR работают во внутренней сети Docker, их порты на хост не публикуются. Имена сетей и контейнеров относятся к Compose-проекту `rapporteur`.

## 3. Проверка после установки

- Страница «Управление» видит Ollama и `qwen3.5:27b`.
- Загрузка текстового выступления дает сводку, а короткая запись — стенограмму и предложение разбиения.
- Ссылки на цитаты открывают правильные страницы/таймкоды.
- После проверки доклада формируются DOCX и PDF.
- В `nvidia-smi` Qwen и ASR размещены на разных выбранных картах.
- Повторите сценарий без внешней сети и после перезапуска. Подробный протокол — в исходном репозитории, `docs/acceptance.md`.

## 4. Обновление существующей установки

Новый интерфейс использует ту же базу, оригиналы и выпущенные справки. Старые ручные привязки открываются на этапе «Доклады». Прежние ссылки `processing` открывают «Проверку», ссылки на отдельные доклады продолжают работать.

1. Сохраните старый комплект вместе с `images.tar.gz`, `.env` и `SHA256SUMS`: он понадобится для отката. Распакуйте новый комплект в **другой каталог**, например `/srv/rapporteur-new`.
2. В старом каталоге выполните `make down`. Не запускайте две версии приложения с одним хранилищем.
3. Найдите `RAPPORTEUR_STORAGE` в старом `.env`. Относительный путь считается от старого каталога. Сохраните весь каталог, включая скрытые и WAL-файлы. Пример для `/srv/rapporteur/storage`:

   ```bash
   mkdir -p "$HOME/rapporteur-backups"
   tar --acls --xattrs -czf "$HOME/rapporteur-backups/storage-before-update.tar.gz" -C /srv/rapporteur storage
   cp /srv/rapporteur/.env "$HOME/rapporteur-backups/env-before-update"
   ```

4. В новом каталоге выполните `make install`. Он проверит комплект и загрузит образы; это ещё не запуск приложения.
5. Перенесите значения старого `.env` в созданный новый. Сохраните порт, адрес, UUID разных GPU, лимиты и выбранный профиль. **Пути задайте абсолютными:** относительные пути старой установки теперь указывали бы на новый каталог. Пример повторного использования весов и хранилища:

   ```dotenv
   OLLAMA_MODELS_DIR=/srv/rapporteur/models
   ASR_MODELS_DIR=/srv/rapporteur/models/asr
   RAPPORTEUR_STORAGE=/srv/rapporteur/storage
   OLLAMA_IMAGE=ollama/ollama:0.40.13
   ```

   В примере старый каталог моделей имеет структуру комплекта (`blobs/`, `manifests/`, `asr/`). Если раньше запускали из исходников, путь Ollama обычно заканчивается на `models/ollama`. Веса повторно скачивать или импортировать не требуется.
6. Выполните `make doctor`, затем `make start` и `make ps`. Compose-проект остаётся `rapporteur`; соседние проекты не останавливаются.
7. Откройте существующую конференцию: проверьте материалы, ручные привязки/границы, проверенные сводки и скачайте ранее выпущенную справку. Затем создайте небольшую тестовую конференцию и пройдите четыре этапа. После `make down` → `make start` данные должны сохраниться.

Схема хранения при этом рефакторинге не меняется. Для более старой базы предусмотрена существующая транзакционная миграция и SQLite-бэкап `rapporteur.db.before-v1.bak`. Он дополняет полный бэкап хранилища.

### Откат

1. В новом каталоге выполните `make down`.
2. Отложите изменённое хранилище в отдельный каталог, чтобы не потерять работу после обновления. Восстановите полный архив на прежний путь. Пример:

   ```bash
   mv /srv/rapporteur/storage /srv/rapporteur/storage-after-update
   tar --acls --xattrs -xzf "$HOME/rapporteur-backups/storage-before-update.tar.gz" -C /srv/rapporteur
   ```

3. Перейдите в **старый** комплект, выполните `make install`, чтобы вернуть прежние образы с локальными тегами. Сохраните старый `.env`.
4. Выполните `make start`; проверьте существующую конференцию и прежнюю справку.

Обновление положения отдела создаёт новую версию. Выпущенные справки сохраняют исходный снимок рекомендаций; текущие результаты после изменения источников могут потребовать повторной проверки.

## 5. Если запуск не удался

| Сообщение/симптом | Действие |
| --- | --- |
| Порт занят | Изменить `WEB_PORT`; не останавливать соседние проекты |
| GPU недоступна | Проверить UUID, драйвер, Toolkit и вывод `nvidia-smi` |
| Две службы используют одну карту | Исправить `LLM_GPU_ID` и `ASR_GPU_ID`, повторить `make doctor` |
| Нет `blobs/` или манифеста | Исправить `OLLAMA_MODELS_DIR`; указать каталог модели целиком |
| Нет `model.bin` | Привезти полный CTranslate2-каталог ASR, исправить `ASR_MODELS_DIR` |
| Permission denied | Проверить чтение моделей и запись в хранилище для UID пользователя make |
| Мало места | Перенести хранилище/модели на подходящий SSD; не удалять оригиналы вручную |
| Ошибка распознавания | Открыть `make logs`, проверить модель ASR и доступность второй GPU |
| Недостаточно VRAM | Проверить чужие процессы, уменьшить контекст/параллельность; не включать обе карты для Ollama |
| Ошибка SHA-256 | Повторно перенести комплект; не обходить проверку |

Состояние: `make ps`. Журнал: `make logs`. Остановка: `make down`. Эти команды сохраняют данные.

## Команды на сервере

Используйте `make install`, `make config`, `make doctor`, `make start`, `make ps`, `make logs` и `make down`. Команды `make check`, `make prepare` и `make bundle` запускаются в полном исходном репозитории на машине подготовки.

## Документация в комплекте

`WORKFLOW.md` — инструкция оператору, `ACCEPTANCE.md` — серверная приёмка, `VALIDATION.md` — фактически выполненные локальные проверки и ограничения. Эти файлы входят в SHA-256.
