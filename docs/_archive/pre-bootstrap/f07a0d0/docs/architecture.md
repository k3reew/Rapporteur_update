# Текущая архитектура

Этот документ описывает текущую реализацию. Старые ADR и спецификация содержат исторические варианты с PostgreSQL, отдельными workers и распределением модели по GPU; эти варианты не являются инструкцией по запуску.

## Данные и конвейер

FastAPI, собранный React и один фоновый Processor работают в сервисе `app`. SQLite использует WAL и короткие транзакции. Вызовы моделей, OCR и конвертация документов выполняются вне транзакций базы. Оригиналы сохраняются по SHA-256, результаты этапов — атомарно в файловом хранилище.

1. Потоковая загрузка определяет формат по содержимому и проверяет размеры. Назначение PDF/TXT можно уточнить отдельно от формата. Повторное содержимое в конференции не создает второй оригинал.
2. «Подготовить» ставит конференцию в очередь. PPTX разбирается существующим парсером, Word конвертируется в PDF, PDF читается постранично, фотографии нормализуются; страницы без текстового слоя проходят Tesseract rus+eng. Qwen отдельно описывает схемы/графики презентаций и фотографий.
3. Внутренний ASR-сервис на второй GPU обрабатывает запись пятиминутными частями через FFmpeg и faster-whisper. Кэш каждой части сохраняется; таймкоды абсолютные. Тишина не порождает фиктивные доклады.
4. Qwen получает окна стенограммы с небольшим перекрытием и предлагает границы. Программа помогает определить тему/автора, но не попадает в фактическую базу доклада. Для файлов без записи используются папки, метаданные и сопоставление содержания. Неоднозначные материалы остаются отдельными предложениями.
5. Человек правит предложение и подтверждает его. `material_links` связывает файл с докладами целиком, по страницам или интервалам времени. Исходный файл не копируется и не разрезается физически.
6. Processor собирает пакет источников каждого доклада. Метки `S` — слайды, `D` — страницы документов/фотографий, `T` — стенограмма, `N` — заметки слушателя, `V` — интерпретация изображения. Цитаты сверяются по исходному тексту конкретной ревизии; числа и отрицания проверяются отдельно.
7. Большие материалы делятся на порции; факты объединяются попарно с сохранением цитат. Результаты порций кэшируются. Визуальные утверждения сохраняют статус `needs_human` до индивидуального подтверждения.
8. Ручная правка и подтверждение создают версии сводки. Запросы используют прочитанную версию; конфликт возвращает HTTP 409. Результат фоновой задачи привязан к `input_revision` и не подменяет актуальные материалы после перепривязки.
9. Рекомендации отделам рассчитываются по подтвержденным фактам и порциям положений. Ссылки на несуществующие факты, версии или пункты отклоняются. Рекомендации подтверждаются отдельно и устаревают при изменении сводки/положений.
10. Справка сохраняет снимок сводок и подтвержденных рекомендаций. DOCX является источником Markdown и PDF; приложение предупреждает о неполных метаданных и пропущенных рекомендациях.

После перезапуска задания `running` возвращаются в очередь. История сводок и справок не перезаписывается.

## Границы модулей

`app.py` создаёт FastAPI, ресурсы, жизненный цикл, обработчики ошибок и статику. `api/` содержит маршруты конференций, файлов, докладов, подготовки/очереди, сводок, отделов, справок и настроек. Предметные правила находятся в прежних модулях `materials`, `preparation`, `processing`, `reviews`, `departments`, `reports`, `summarize/` и `report/`.

`Database.read()` открывает согласованный снимок с `query_only`, не резервируя место писателя. `Database.tx()` использует `BEGIN IMMEDIATE`; HTTP-записи фиксируются до отправки ответа (`Depends(..., scope="function")`). Модели, извлечение и рендеринг выполняются между короткими транзакциями чтения и записи. Оригиналы публикуются жёсткой ссылкой с того же тома, кэш — атомарным переименованием; ключи кэша не менялись.

Во frontend HTTP-запросы находятся в `api.ts`, типы и статусы отделены от экранов. `useResource` отменяет запросы при уходе, выполняет опрос без перекрытия и игнорирует ответы, начатые до сохранения или смены страницы. Черновики разбиения и рекомендаций держат исходную версию отдельно от фонового опроса. `useUnsavedChanges` защищает формы; редактор сводки предлагает сохранить/отменить перед переходом.

Адреса этапов: `#/c/{id}/materials`, `talks`, `review`, `report`. Старый `processing` совместим с `review`. Прямые ссылки `#/c/{id}/talk/{talkId}` сохранены. Состояние этапа восстанавливается через API при открытии страницы.

## Размещение

- `app`: CPU; лимиты CPU/RAM задаются окружением.
- `ollama`: одна явно выбранная GPU, Qwen3.5 27B Q4_K_M, один запрос одновременно, контекст 32K.
- `asr`: другая явно выбранная GPU, Whisper large-v3 FP16.
- Публикуется только веб-порт, по умолчанию `127.0.0.1:18763`. Доступ к внешней Ollama — отдельный режим для доверенной корпоративной Docker-сети.
- Модели подключаются только для чтения; оригиналы, база и рабочий кэш находятся на SSD. Внешние API при обработке не используются.

## Известные ограничения

- Качество и производительность на A100 и реальных материалах должны быть подтверждены отдельным протоколом; автоматические тесты используют предсказуемые ответы модели.
- Диаризация с установлением личности по голосу не выполняется. Автор определяется по явно названным сведениям и подтверждается оператором.
- Интервалы, заданные вручную внутри одного сегмента ASR, исключают пересекающий границу сегмент из фактов, чтобы не переносить чужую речь. Используйте прослушивание и границы распознанных реплик; оригинал всегда остается доступен.
- Основной сценарий — записи до 10 часов каждая. Это не система горизонтального масштабирования; Processor один. Первая обработка большого числа изображений/положений может быть длительной.
- Максимум 300 страниц и 200 МиБ на документ, 5 МиБ на TXT/MD, 10 ГиБ и 10 часов на запись. Парольные и поврежденные документы отклоняются.
- Нативный текст PPTX/PDF предпочтительнее OCR. Описания графиков не являются автоматически подтвержденным доказательством.
- Встроенных аккаунтов и разграничения доступа нет; установка предназначена для доверенного рабочего места/шлюза.

## Подтверждение реализации

`tests/test_app.py`, `tests/test_slides.py`, `tests/test_verify.py` и тесты сборки проверяют прежний конвейер. `tests/test_multimodal.py` проверяет новые сценарии документов, версий, массового подтверждения, положений и изоляции источников. Тесты интерфейса используют HTTP-заглушки. Реальный инференс и сеть закрытого контура проверяются по `acceptance.md`.

Фикстура `tests/fixtures/legacy-installation.tar.gz` содержит вымышленные материалы из установки до редизайна: ручной реестр, разбиение записи и выпущенную справку. `tests/test_upgrade.py` проверяет их открытие и SHA-256 всех старых экспортов. `tests/test_read_transactions.py` проверяет чтение при записи и фиксацию изменений до HTTP-ответа.
