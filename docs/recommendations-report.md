# Рекомендации отделам и выпуск справки

## Содержание документа

<!-- codebase-analysis-ai:scope:start -->
Версии положений отделов, расчёт рекомендаций, их подтверждение и включение в справку. Описаны правила отбора докладов, метаданные, форматы и история выпущенных документов.
<!-- codebase-analysis-ai:scope:end -->

## Контекст

Рекомендация связывает подтверждённый факт доклада с обязанностью отдела из загруженного положения. Оператор проверяет объяснение и опоры. При выпуске справки приложение сохраняет снимок этих оснований вместе со сводками выбранных докладов.

Положение является версионным документом. Изменение положения или сводки влияет на актуальность текущего расчёта. История выпущенных справок содержит данные, использованные при конкретной сборке.

## Ответственность компонентов

API отделов принимает документ и извлекает страницы. `departments.py` управляет версиями, порциями текста, расчётом, проверкой опор и снимками. `reports.py` получает данные и сохраняет версию справки. `report.assemble` формирует выборку и переменные, `report.build` и `report.export` создают файлы по бланку.

Оператор решает, полезен ли доклад отделу в контексте организации, и подтверждает рекомендацию. Авторитетное название, докладчики и организации берутся из реестра докладов.

## Как это работает

### Положения и расчёт

При загрузке положения задаются название отдела и имя файла. Без `department_id` создаётся отдел, с существующим идентификатором — следующая версия. Поддерживаются DOCX, DOC, PDF и текст. После извлечения должны остаться непустые страницы.

Каждая страница делится на порции по 2000 символов. Локатор `p2.3` обозначает третью порцию второй страницы. Расчёт разрешён для доклада `reviewed` при наличии положений. Для каждого положения и порции выбираются подтверждённые утверждения пачками по 12.

Модель возвращает `department_id`, `department_version`, объяснение, `claim_ids` и `paragraph_ids`. Код проверяет, что опоры принадлежат текущей порции, подтверждённым фактам и известной версии отдела. Модель может вернуть пустой список. Одна конференция может содержать доклады, интересные нескольким отделам.

Перед сохранением повторно сравниваются версия сводки, реестр версий отделов и статус доклада. Изменение исходных данных во время расчёта завершает задачу ошибкой для повторного запуска.

### Проверка и актуальность

Оператор редактирует объяснение, удаляет лишние рекомендации и отправляет прочитанную версию. Сервер проверяет версию и актуальность, валидирует ссылки и увеличивает номер версии после подтверждения.

Сохранённый расчёт содержит номер сводки и словарь текущих версий всех отделов. Если изменится хотя бы один элемент этого словаря или текущая версия сводки, результат будет показан как устаревший. Эта проверка шире изменения только рекомендованного отдела. Для экспорта подходят подтверждённые актуальные результаты.

### Отбор и сборка

Сборка получает `talk_ids` либо выбирает все доклады конференции. Пустой явный список отклоняется. Подготовка входа требует хотя бы одной непустой сводки и дат для периода. Счётчики вычисляет код по фактически вошедшим докладам. Число докладчиков считается по нормализованным уникальным именам с ролью `speaker`.

| Условие доклада | Поведение при сборке |
| --- | --- |
| `reviewed`, непустая сводка, допустимые утверждения | Включение в справку |
| `processed` или `stale` с непустой сводкой | Требуется `unreviewed_confirmed=true`, выдаются предупреждения |
| `needs_attention` у сводки с подходящими опорами | Возможное включение по правилам статуса доклада с предупреждением |
| Использованное утверждение `needs_human` | Пропуск доклада до подтверждения человеком |
| Пустая сводка, отсутствие сводки, `draft`, `matched`, `not_held`, `insufficient_data` | Пропуск с причиной |
| Непроверенная или устаревшая рекомендация | Пропуск рекомендации с предупреждением |

Непроверенный допуск является осознанным действием оператора. Он допускает в том числе старую сводку с предупреждением и не заменяет проверку её актуальности. Для штатного выпуска следует обработать изменённые источники и проверить новую сводку.

Метаданные справки берутся из реестра, а текст — из текущих сводок. При неизвестном авторе бланк выводит «Автор не установлен», для отсутствующей темы применяется текст о неустановленной теме. Период определяется выбранными днями, датами докладов/секций или датами конференции.

DOCX создаётся по бланку Jinja/docxtpl. Из него получается Markdown, PDF рендерится LibreOffice. Версия хранит вход, переменные, предупреждения, ключи файлов, их размеры и SHA-256. При скачивании проверяется целостность файла. Повреждение даёт HTTP 500 с сообщением для оператора.

## Доступные функции

В интерфейсе доступны загрузка нового положения и новой версии, просмотр распознанных страниц, расчёт и подтверждение рекомендаций в контексте доклада. После изменения источников требуется актуализировать расчёт.

На этапе справки доступны сохранение дат и места, выбор докладов, явный допуск непроверенных сводок, сборка новой версии и скачивание трёх форматов. Сохранённая версия связана со снимком данных. Повторная сборка создаёт следующий номер.

Пользовательский сценарий и контракт поддерживают ручную проверку оснований. Автоматическое совпадение темы доклада с названием отдела не служит достаточным основанием рекомендации. Для оценки качества требуется сравнить вывод с экспертной разметкой обязанностей и фактов.
