# Словарь терминов

## Содержание документа

<!-- codebase-analysis-ai:scope:start -->
Термины предметной области и реализации, используемые в документации «Репортёра». Определения помогают читать пользовательские и технические разделы одинаково.
<!-- codebase-analysis-ai:scope:end -->

## Контекст

Одно слово «проверка» используется для нескольких действий. В документации уточняется, выполняет ли её схема данных, алгоритм цитат, оператор, тест или экспериментальная оценка качества.

## Справочные сведения

Термины сгруппированы в одном справочнике.

| Термин | Значение |
| --- | --- |
| Материал | Загруженный оригинал, зарегистрированный в конференции. |
| Назначение файла | Роль presentation, document, notes, program, image, audio или video, влияющая на извлечение и использование. |
| Доклад | Запись реестра с темой, авторами, порядком и связанными источниками. |
| Предложение | Версионный результат подготовки, который оператор редактирует до подтверждения. |
| Привязка | Связь файла с докладом целиком, по страницам или по времени. |
| Фрагмент | Текст с видом, происхождением и локатором в источнике. |
| Локатор | Страница, строки или временной интервал исходника. |
| Пакет фрагментов | Совокупность источников одного доклада с уникальными метками. |
| Метка | Короткая ссылка S4, D2, T1.00:00:09, N1 или V3 внутри пакета. |
| Ревизия | Идентификатор редакции текста или числовая версия входов, используемая для согласованности. |
| Факт модели | Черновая содержательная запись с цитатами, полученная в FactsDraft. |
| Утверждение | Факт после сверки опор с ключом c1, типом и статусом Claim. |
| Доказательная опора | Evidence с меткой, цитатой, ревизией фрагмента, span и match_score. |
| Сверка цитаты | Алгоритмический поиск текста и проверка чисел/отрицаний в источнике. |
| Подтверждение человеком | Осознанная проверка результата оператором с записью новой версии. |
| Сводка | Текст одного доклада с предложениями, выводами и ссылками claim_ids. |
| Справка | Версионный документ по выбранным докладам конференции. |
| Положение | Загруженный документ об обязанностях отдела с историей версий. |
| Рекомендация | Соответствие фактов доклада обязанностям отдела с основаниями по пунктам положения. |
| Предварительный отбор | Версионная оценка связи исходных материалов доклада с обязанностями отделов, определяющая, получит доклад сводку или только карточку (`interest.py`). |
| Задание выпуска | Сохраняемая сборка справки с неизменяемым снимком входов и шаблона, состоянием, попыткой и единственной опубликованной версией. |
| Проверка понятности | Результат reader_context, оценивающий самостоятельность сводки для нового читателя отдельно от смысловой опоры. |
| Кэш | Повторно используемый результат по содержимому и настройкам. |
| SHA-256 | Криптографический хеш для адресации и проверки целостности. |
| LLM | Большая языковая модель для структурированного анализа и генерации. |
| VLM | Модель, принимающая изображения и текст, для визуального описания. |
| ASR | Автоматическое распознавание речи в текст с таймкодами. |
| OCR | Оптическое распознавание текста на изображении. |
| DTO | Структура данных запроса или ответа API. |
| WAL | Журнал SQLite Write-Ahead Logging, участвующий в целостности рабочего состояния. |
| ADR | Запись архитектурного решения с контекстом, выбором и последствиями. |

`verified` обозначает результат автоматической сверки опоры. `confirmed` фиксирует проверку человеком. Успех HTTP-запроса запуска, завершение задачи и проверка сводки отражаются разными состояниями. Термины «факт» и «утверждение» описывают объекты приложения и способ их получения.
