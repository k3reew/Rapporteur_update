# «Репортёр» 0.5.0 в закрытом контуре

Комплект для Linux amd64 содержит приложение, vLLM 0.32.0, Qwen3.5‑27B BF16 и GPTQ Int4, лицензии, контрольные суммы и вымышленные материалы. vLLM получает модели из локальных каталогов. Порт модели доступен в частной сети Compose.

## Установка

1. Скопируйте каталог комплекта целиком, включая `.env.example`, на внутренний диск сервера. Проверьте место для комплекта, распакованных Docker-образов и рабочего хранилища.
2. Убедитесь, что доступны Docker Engine, Docker Compose, NVIDIA Container Toolkit, Python 3, GNU Make и драйвер NVIDIA. Откройте оболочку в каталоге комплекта и выполните `make install`. Команда сверяет SHA-256, загружает локальные образы и создаёт `.env`, если файл отсутствует.
3. Настройте `RAPPORTEUR_STORAGE` на файловой системе Linux и задайте свободный порт. По умолчанию веб-порт доступен на `127.0.0.1:18763`. Подставьте UUID видеокарт из `nvidia-smi -L` в `VLLM_GPU_ID_0` и, если используется вторая карта, `VLLM_GPU_ID_1`.
4. В `.env` выберите режим. Модель запускается с контекстом 32K во всех профилях.

   | `VLLM_MODE` | Карты | Модель | Одновременные запросы |
   | --- | --- | --- | --- |
   | `bf16` | 2 × A100 40 ГБ | Qwen3.5‑27B BF16, TP2 | До двух через один экземпляр |
   | `gptq-dual` | 2 × A100 40 ГБ | Qwen3.5‑27B GPTQ Int4, TP1 на каждой | Один на экземпляр |
   | `gptq-single` | 1 × A100 40 ГБ | Qwen3.5‑27B GPTQ Int4, TP1 | Один |

5. Выполните `make config`, `make doctor`, `make start` и `make ps`. `make start` приводит службы выбранного режима в рабочее состояние с `--no-build --pull never`. В «Настройках» отображается активная модель и готовность каждого экземпляра.
6. Для переключения режима остановите установку командой `make down`, измените `VLLM_MODE` и снова выполните `make start`. База, материалы и справки сохраняются в хранилище. Выполните [серверную приёмку](acceptance-0.5.0.md) и [операторский сценарий](workflow-0.5.0.md) на отдельном хранилище.

## Обновление и откат

1. Сохраните прежний комплект, его `.env` и локальные образы. Остановите прежнее приложение и сделайте полную копию рабочего хранилища. В копию входят SQLite, оригиналы, расшифровки, кэш и готовые справки.
2. Запустите 0.5.0 на второй копии хранилища с отдельными `COMPOSE_PROJECT_NAME` и портом. Проверьте открытие старой конференции, скачивание её справки и выпуск новой конференции по новому маршруту. Миграция SQLite выполняется при старте.
3. После приёмки подключите рабочее хранилище к одному экземпляру 0.5.0. Сохраните резервную копию на весь период переключения.
4. Для отката остановите 0.5.0 и запустите предыдущую поставку на сохранённой копии, сделанной до миграции. Изменения, сделанные после переключения, сохраните отдельно для последующего переноса.
