## Состояние проекта

Версия **0.5.0** анализирует материалы конференции, предлагает реестр докладов и оценивает их соответствие отделам. Оператор подтверждает реестр и назначения, затем проверяет и выпускает справку. vLLM работает с Qwen3.5‑27B BF16 на двух A100 или с GPTQ Int4 на одной или двух картах. [Установка и обновление](docs/release-0.5.0.md).

## Быстрый запуск

### Локальная проверка с Ollama

Подключите приложение к Ollama, уже запущенной на компьютере с Docker Desktop. [Настройка и запуск](docs/ollama.md#ollama-на-хосте-docker-desktop).

### Готовый офлайн-комплект

На сервере должны быть Docker Compose и NVIDIA Container Toolkit. Порядок переноса, выбора GPU и каталогов приведён в [офлайн-инструкции 0.5.0](docs/release-0.5.0.md). В каталоге перенесённого комплекта выполните команду.

```bash
make install
```

Открыть созданный `.env`, указать абсолютные каталоги моделей и хранилища, UUID GPU, профиль `VLLM_MODE` и свободный порт. Затем выполнить команды.

```bash
make config
make doctor
make start
make ps
```

При стандартных настройках интерфейс открывается по адресу `http://127.0.0.1:18763`. Для доступа с другого рабочего места администратор задаёт `WEB_BIND_ADDRESS` и использует адрес сервера. Полная инструкция объясняет каждый параметр и первый вымышленный сценарий.

### Подготовка на машине с сетью

В полном репозитории скопировать `.env.example` в `.env`, настроить пути и GPU, затем подготовить модели и комплект.

```bash
cp .env.example .env
make prepare-vllm BUNDLE=/путь/к/комплекту
make bundle-vllm BUNDLE=/путь/к/комплекту
```

Полный комплект создаётся в каталоге `BUNDLE`. При переносе сохраните все файлы, включая `.env.example`.

## Доступные функции

- Загрузка файлов и папки с частичными ошибками и дедупликацией.
- Подготовка отделов, загрузка материалов, автоматический анализ, проверка и выпуск справки.
- Чтение текста документов и слайдов, OCR и описание графиков.
- Группировка разноимённых файлов по докладам и редактирование реестра, авторов, организаций и контактов.
- Процентные оценки по отделам, проверяемые источники и сводки по подтверждённым назначениям.
- Версии положений отделов, проверяемые основания рекомендаций и контроль их устаревания.
- Версии справок DOCX, Markdown и PDF с авторами и темами докладов.
- Светлая, тёмная и системная темы, защита черновиков, повторный запуск задач.

Подробный [каталог функций](docs/product.md) связан с реализацией, [руководство оператора](docs/workflow-0.5.0.md) проходит весь путь на вымышленном примере.

## Устройство приложения

Браузер работает с FastAPI `/api/v1`. SQLite и файловое хранилище сохраняют реестр, задания, версии и оригиналы. Один Processor использует до двух исполнителей для независимых файлов и докладов. Два независимых исполнителя используют общий сервис BF16 или пару экземпляров GPTQ. [Архитектура](docs/architecture.md).

## Технологии

Python 3.12, FastAPI, Pydantic, SQLite, React, TypeScript и Vite. Обработка использует vLLM/Qwen, Tesseract, Poppler, PDFium, LibreOffice и docxtpl. Версии зафиксированы в lock-файлах и образах. Шрифты и ресурсы интерфейса локальные.

| `src/rapporteur/` | API, предметная логика, обработка, хранение |

| `tests/` | Python-тесты и вымышленные примеры |

## Настройка

Профили `server-vllm` и `server-vllm-gptq` закрепляют модели и контекст 32K. Каталоги, UUID карт, режим и порт задаются в `.env`. Готовность экземпляров видна в настройках. [Режимы прежнего профиля Ollama](docs/ollama.md).

## Проверки

В полном репозитории `make check` выполняет линтеры, типы, Python/frontend-тесты и production-сборку. Протокол 14 ноября 2026 фиксирует 253 Python- и 27 frontend-тестов, реальный локальный путь с Qwen3.5:4b на RTX 2060 и Whisper CPU, офлайн-запуск и восстановление старых данных. ## Продолжение разработки

**Актуальная версия находится в `main`.** В неё сведены выпуск 0.3.0, изменения коллеги и исправления аудита. Остальные release/feat/codex-ветки — сохранённая история. Новая задача начинается от `origin/main`, PR направляется в `main`; [правила веток](docs/git.md).

[HANDOFF.md](HANDOFF.md) содержит состояние объединённой разработки, исправления аудита, команды проверки и стартовый запрос для нового чата. [Протокол исправлений](docs/benchmarks/2026-11-18-audit-fixes.md) фиксирует условия локальной проверки.

## Permission denied после переноса

Отказ записи в `/data/cache/vision` связан с доступом к вложенным данным. Проверка: `make storage-check`. После остановки и полного бэкапа: `make storage-repair`, затем `make start`. [Инструкция и автономное исправление старой офлайн-установки](docs/storage-permissions.md). Модели и образы для ремонта скачивать не требуется.
