# Промпты

Промпты лежат в версионируемых файлах (spec §9, принцип 5). Используется путь `prompts/<шаг>/<версия>.md`. Версию выбирает профиль модели (`prompt_version` в [profiles.yaml](../profiles.yaml)), она попадает в результат шага и в `Summary.prompt_versions`, а через профиль — в ключ кэша.

| Шаг | Файл | Ответ модели |
| --- | --- | --- |
| А. Факты и цитаты | [facts/v2.md](facts/v2.md) | `FactsDraft` |
| Сверка фактов по контексту | [facts-review/v2.md](facts-review/v2.md) | `FactsDraft` |
| В. Текст сводки | [summary/v2.md](summary/v2.md) | `SummaryDraft` |
| Смысловой критик | [critic/v2.md](critic/v2.md) | `GroundingReview` |

Активные профили выпуска 0.2.1 используют v2. Исторические [facts/v1.md](facts/v1.md) и [summary/v1.md](summary/v1.md) сохранены. Проверки цитат и решение оператора выполняются отдельно от смыслового критика.

## Формат файла

Свободное описание, затем три раздела:

- `## system` — правила для модели;
- `## user` — материалы доклада или утверждения;
- `## repair` — замечания к предыдущему ответу: ошибки схемы и связей полей на шаге А, непройденные проверки на шаге Г.

Текст раздела — шаблон Jinja. Неизвестная переменная — ошибка, а не пустое место. Какие переменные доступны, написано в описании каждого файла. JSON Schema ответа в текст не входит: код передаёт её в `format` запроса к Ollama (ADR-010).

## Как менять

Промпт не правится на месте: новая редакция — новый файл `v2.md` и новый профиль или новая `prompt_version` в профиле. Старые результаты остаются воспроизводимыми, а новые не берутся из кэша. Сравнение на размеченном корпусе должно сохранять ошибки и все назначенные запуски. `make eval` остаётся историческим требованием спецификации. Фактические проверки выполняются через `make check` и датированный исследовательский протокол.

Материалы конференций в промпты и примеры не копируются: примеры в промптах вымышленные (spec §16).

## Выпуск 0.3.0

Штатные профили используют v3 для facts, facts-review, summary и critic. Критик возвращает раздельные смысловые решения и reader_passed/reader_issues. Сводка знакомит нового читателя с докладом, обычно содержит 6–10 предложений. Объём адаптируется к подтверждённым сведениям. v1 и v2 остаются доступны для сохранённых профилей. [Описание выпуска](../docs/release-0.3.0.md).
